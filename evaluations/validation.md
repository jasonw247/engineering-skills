## Method and limits

Evaluators received isolated copies of the skill and raw task inputs, without the acceptance answers or author conclusions. Routing decisions used only the name/description before loading the body. The author reviewed the resulting artifacts and independently reran the meaningful executable checks. Behavioral trial code is retained as evidence, not shipped as a production utility.

The document trial was interrupted by a server restart after its initial routing check. A fresh evaluator resumed the behavioral tasks from the isolated skill and raw inputs. The later evaluators each handled several skills sequentially; these are focused forward trials, not statistically independent experiments.

The code-review case originally proposed treating full sorting and reversed tie ordering as separate regressions. Inspection showed that full sorting predated the patch and timestamp deduplication made the proposed tie-order path unreachable. The acceptance case was corrected to require demonstrated findings. The evaluator independently found both data loss and a measured allocation increase; it did not receive the proposed findings.

Cases without suitable supplied implementations or fixtures remain **not run** in their records. A supplementary simple-request workflow design checks that the skill permits a single validated model call; it does not complete the separate implementation case. Metadata routing checks do not exercise a host's automatic skill discovery. No provider mutations, external model calls, global skill installation, or current vendor/API audit were part of these trials.

No matched trials without skills were performed. Passing outcomes show that the instructions support these requests without violating the tested boundaries; they do not prove that the skills caused better results or establish production readiness.

## Reproduce the executable evidence

From the relevant retained `runs/2026-10-12/work/` directory:

- Python service: run `python3.12 -B -m unittest -v`.
- Code review: run `python3 -B reproduce.py`; allocation values depend on the interpreter and platform.
- RAG evaluation: run `python3 -B evaluate.py`; this rewrites the local synthetic `results.json`, including diagnostic timings.
- Python setup: follow `delivery.md` to build/install in temporary isolated environments and run the five tests from outside the package checkout. Offline reproduction needs locally available setuptools and wheel.
